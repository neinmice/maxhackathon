# Contribution guide

1. Создай ветку `feat/...`, `fix/...` или `docs/...`.
2. Прочитай `AGENTS.md` и профильную задачу.
3. Не смешивай frontend/backend/docs в одном PR без причины.
4. Запусти проверки своего слоя.
5. В PR укажи: цель, изменённые файлы, тесты, ограничения, evidence.
6. Merge в `main` выполняется после review владельца слоя и Стаса.

## Ownership

Sasha owns the GitHub workflow: project board, branch policy, CI, technical review, approvals, merges and release tags. Stas provides product/visual sign-off and final review of user-facing behavior; Pasha owns frontend implementation.
