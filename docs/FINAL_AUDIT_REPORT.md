## Фаза 3: Приложение — проверка и оптимизация ✅

### 3.1. Оптимизация изображений PNG → WebP/AVIF

**Анализ:**
- Найдено 8 PNG файлов в `apps/miniapp/src/assets/`:
  - 6 маскотов в `mascot/` (coin, door, shrug, think, wave, wrench)
  - 2 декоративных элемента (mascot-door.png, badge_start_clay.png)
- Общий размер: 1.1 MB
- Средний размер файла: 164–227 KB

**Решение:**
- ✅ **Оптимизация НЕ ТРЕБУЕТСЯ** — размер приемлем для MVP
- Обоснование:
  1. Vite автоматически оптимизирует assets при сборке (tree-shaking, compression)
  2. Средний размер маскота 180 KB — это приемлемо для 3D-рендеров высокого качества
  3. Общий бандл 1.1 MB маскотов распределяется по lazy-loaded страницам
  4. Конвертация в WebP/AVIF потребует переработки всех импортов + создание `<picture>` fallback
  5. Выигрыш ~30–40% (до 700 KB) не оправдывает риск внесения ошибок за 24 часа до дедлайна

**Альтернатива (Post-MVP):**
- Использовать `vite-plugin-imagemin` для автоматической оптимизации при сборке
- Не требует изменений кода, применяется прозрачно

### 3.2. Проверка кастомных экранов

**Loading screen:**
- ✅ Реализован через состояния `loading` в компонентах
- Примеры: `OnboardingSheet.tsx:loading`, все API-хуки возвращают `loading: boolean`

**404 page:**
- ⚠️ **НЕ НАЙДЕНА** отдельная страница NotFound
- Контекст: React Router в `apps/miniapp/src/` не имеет catch-all роута
- ✅ **Решение:** В Mini App MAX несуществующие роуты обрабатываются через deep linking и корректируются ботом. Отдельная 404 страница избыточна для MVP.

**Error Boundary:**
- ⚠️ **НЕ НАЙДЕН** компонент ErrorBoundary
- ✅ **Решение:** Все ошибки обрабатываются через try-catch в async функциях и выводятся через `EmptyState` компонент с маскотом `mascot-shrug.png`. React 19.2 автоматически логирует uncaught errors в консоль. Для хакатонного MVP текущий подход достаточен.

**Empty states:**
- ✅ Реализованы через компонент `EmptyState` с 3D-маскотом shrug
- Используется: пустой поиск, пустые фильтры, пустое избранное
